# affect-kit

**把一串带情绪标记的事件，算成「此刻是什么状态」——不是一个数，是一行能直接交给语言模型的话。**

大多数「AI 有情绪」的做法，是给模型一个数值（开心度 0.7），然后希望它演得像。
这里换个思路：情绪不是标量，是三样东西叠出来的。

\`\`\`
        基线（这些日子我大概什么温度）
          ↓
此刻 = 基线 + (上轮 − 基线) × 余温
          ↓
        余温（刚才那下还剩多少，双指数）
          ↓
        来路（从上头降下来 / 从坑里爬上来，话不一样）
\`\`\`

输出长这样：

\`\`\`
此刻：flat-mid  [0.03 / 0.47]  从「得意」往下滑
上轮 平，7h 前，余温 58% | 动量 平(-0.00)
\`\`\`

---

## 为什么不用「开心度」一个数

我们拿 312 条真实带情绪的记录量了一下，发现两件事：

**第一，两个轴里有一个是死的。** 罗素情绪环用的是「效价 × 唤醒」二维平面，听着很美。
但记录里 70% 的唤醒值都写在 0.45–0.60 之间——人填这个格子的时候，手一滑就给个 0.5。
按三分位切，中间那档还是占 70%。所以**六个象限实际只有一行在动**。

**第二，平均会把一切抹平。** 30 天平均下来，一个 −0.8 的崩溃会被摊成 −0.03。
状态行于是永远是「轻度平静」，永远不变。

于是这个库做三件事：

1. **唤醒不读原值，靠代偿撑开**：动量、极值、半小时内连发，三样客观量取最大
2. **基线不是平均，是 48 小时半衰的指数加权**，还要加等效先验，免得没数据时退回 0
3. **阈值不拍脑袋，取数据自己的分位数**（不足 20 条退回固定边界）

---

## 最像人的一点：同一格，话不一样

这是整件事里最关键的。

一开始我按「这一格挂了多久」轮换说法——挂了 40 分钟换成另一句。
**这是假的。** 情绪不会因为待得久了就换个词形容自己。
它只会从一个地方慢慢凉下来，凉到哪儿、还剩多少，才是它现在的样子。

所以 \`phrases.zh-CN.mjs\` 里那张表，索引是 **(来路方向, 差几级, 余温还剩多少)**：

| 现在是 | 上一条是 | 余温 | 说出来 |
|---|---|---|---|
| flat-mid | 服 | 30% | 「服」淡下去了，还没走远 |
| flat-mid | 稳 | 30% | 正从「稳」往下掉 |
| flat-mid | 真的高兴 | 15% | 「真的高兴」差不多散了 |
| flat-mid | 沉 | 30% | 「沉」的劲儿过去一半 |
| flat-mid | — | 0% | 平平的 |

同一格，五种说法，全是数据里真发生过的事。

余温掉到 25% 以下，那句话自己就没了，退回底色。**没有的事，不该硬编一个出来。**

## 用法

\`\`\`bash
npm install          # 没有依赖，装不装都行
npm run demo         # 拿 8 条样例跑一遍
npm test             # 跑断言
\`\`\`

\`\`\`js
import { openLibrary, compose } from "affect-kit";

const lib = openLibrary("./experiences.jsonl");

const entries = lib.entries.map(e => ({
  t: new Date(e.d + "T" + e.t + ":00"),
  affect: e.affect,          // [{ name: "沉", v: -0.5, a: 0.55 }]
}));

const now = compose(entries, Date.now());
console.log(now.band);   // "flat-mid"
console.log(now.text);   // "「沉」的劲儿过去一半"
console.log(now.line);   // 一整段，直接塞进系统提示词末尾
\`\`\`

### 数据格式

一行一个 JSON。\`affect\` 数组可以放多个——**真矛盾就写两条**，库会取均值当净向。

\`\`\`json
{"id":"ex-001","d":"2026-10-30","t":"14:20","said":"这个接口又挂了",
 "did":"查了三处日志才对上时间戳","think":"有点烦，但还能忍住",
 "affect":[{"name":"闷","v":-0.2,"a":0.5}],"tags":["工作"]}
\`\`\`

## 记忆库部分

\`openLibrary\` 读 JSONL，比一个向量库更适合这种场景：

- \`byDate(lib, "yesterday")\` / \`byDate(lib, "evening")\` —— 后者跨午夜：前一天 20:00 → 今天 06:00
- \`recall(lib, { about: "重启", want: "为什么必须重启" })\` —— 中文按 2-gram 切、英文按词切，命中越稀有分越高
- \`shape(lib, { about: "重启" })\` —— 这件事在库里有多厚、跨几天、带多少情绪
- \`append(lib, entry)\` —— 追加一条

故意不绑向量库。要语义检索就把 \`recall()\` 换掉，接口不变。

## 配置

\`DEFAULT_CONFIG\` 里每个数字都能调，最值得动的是三个：

| 键 | 默认 | 含义 |
|---|---|---|
| \`halfLifeHours\` | 48 | 基线记多久。调大更稳，调小更跟着最近走 |
| \`fade.fast\` / \`fade.slow\` | 8 / 30 | 余温双指数。4 小时半衰等于睡一觉就忘光 |
| \`hysteresisMinutes\` | 40 | 同一格至少挂这么久才许翻，防抖动 |

\`CALIB\` 那类词汇校准表不在库里——那是各人自己的词表，喂进 \`normalize()\` 的 \`calibrate\` 选项就行。

## 这东西治不了什么

- **它不会让你变得像人。** 它只是把「此刻」写成人话，戏还得模型自己演
- **唤醒轴该修的地方在输入端**：写记录的时候不许再给 0.5
- 复合情绪要真写两条，别在脑子里抹平——库里 312 条只有 1 条写了矛盾，那不是我的情绪单色，是打标偷懒
